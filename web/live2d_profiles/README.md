# Live2D 模型适配档案：手势与角色响应对照说明

本目录用于存放各 Live2D 模型的适配档案（profile）。当前项目接入 **Haru** 模型，
对应配置文件为 [`haru.js`](./haru.js)。

> 说明：本文档为配置说明，实际生效的参数定义于 `haru.js`。当修改 `haru.js` 中的
> `RESPONSE_MAP`，或修改 [`gesture/command_mapper.py`](../../gesture/command_mapper.py) 后，
> 应同步更新本文档，以保持文档与代码一致。

---

## 1. 手势到角色响应的处理流程

系统将用户手势转换为角色动作的完整链路如下：

```
摄像头采集用户手部图像
  → MediaPipe 提取 21 个关键点
  → 计算五指状态 [拇指, 食指, 中指, 无名指, 小指]   （gesture/finger_state.py）
  → 识别手势名称（如 V_SIGN）                       （gesture/gesture_classifier.py）
  → 映射为控制命令（如 CMD_HAPPY_POSE）             （gesture/command_mapper.py，Python 端）
  → 经 UDP 发送至 Bridge，再经 WebSocket 转发至前端
  → 前端依据命令查询 RESPONSE_MAP                   （haru.js）
  → 驱动角色：播放动作、切换表情、语音播报、舞台灯光
```

控制命令共有三类来源，优先级由高到低如下：

1. **动态挥动命令**：由手部快速移动触发，优先级最高；
2. **空间与双手命令**：由手部所处区域或双手组合触发；
3. **静态手型命令**：由固定手部姿态触发，优先级最低。

> 此外，头部与眼部追踪为常驻功能，不属于上述手势命令：角色头部与视线会持续朝向
> 用户手部所在位置，仅在播放上述动作的短暂时段内被动作姿态临时覆盖。

## 2. 静态手型手势

`fingers` 数组顺序为 `[拇指, 食指, 中指, 无名指, 小指]`，取值 `1` 表示伸出，`0` 表示弯曲。

| 手势名称        | 手指状态                        | 操作方式                     | 控制命令           | 角色响应（名称 · 表情 · 动作 · 语音 · 灯光）                     |
| --------------- | ------------------------------- | ---------------------------- | ------------------ | ---------------------------------------------------------------- |
| **FIST**        | `00000`                         | 握拳                         | `CMD_IDLE`         | 安静待机 · F01 · Idle · “好，我先安静一下” · 冷静浅蓝            |
| **OPEN_HAND**   | `11111`                         | 五指张开                     | `CMD_WAVE`         | 挥手回应 · F05 · m05 · “你好呀，我看到你的手势啦” · 制服柔光     |
| **INDEX_UP**    | `01000`                         | 仅伸出食指                   | `CMD_ATTENTION`    | 认真聆听 · F02 · m06 · “嗯，我在听，请继续” · 制服柔光           |
| **V_SIGN**      | `01100`                         | 食指与中指伸出（剪刀手）     | `CMD_HAPPY_POSE`   | 开心合影 · F05 · m26 · “耶，这个手势很适合拍照” · 制服柔光       |
| **THUMBS_UP**   | `10000`（拇指指尖位于手腕上方） | 竖起拇指朝上                 | `CMD_PRAISE`       | 接受赞许 · F05 · m08 · “谢谢夸奖，我会继续加油” · 制服柔光       |
| **THUMBS_DOWN** | `10000`（拇指指尖位于手腕下方） | 拇指朝下                     | `CMD_DISAPPOINTED` | 略显委屈 · F08 · m13 · “我会再调整一下，不要失望嘛” · 冷静浅蓝   |
| **ROCK**        | `11001`                         | 拇指、食指与小指伸出         | `CMD_DANCE`        | 舞台活跃 · F05 · m10 · “节奏来了，进入舞台模式” · 舞台暖光       |
| **CALL**        | `10001`                         | 拇指与小指伸出（电话手势）   | `CMD_TALK`         | 通话回应 · F01 · m07 · “喂喂，HandPilot 通信正常” · 制服柔光     |
| **THREE**       | `01110`                         | 中间三指伸出                 | `CMD_SURPRISE`     | 惊讶反应 · F02 · m11 · “哇，三根手指触发了惊喜” · 制服柔光       |
| **FOUR**        | `01111`                         | 四指伸出（不含拇指）         | `CMD_CHEER`        | 应援鼓励 · F05 · m24 · “收到四指信号，给你加油” · 舞台暖光       |
| **FOUR_THUMB**  | `11110`                         | 四指伸出（含拇指，不含小指） | `CMD_SHY`          | 害羞回应 · F07 · m17 · “这个手势有点可爱，我有点害羞” · 害羞粉光 |
| **PINKY_UP**    | `00001`                         | 仅伸出小指                   | `CMD_PROMISE`      | 拉钩约定 · F07 · m16 · “勾一下小指，这是我们的约定哦” · 害羞粉光 |

## 3. 动态挥动手势

由 [`gesture/hand_motion.py`](../../gesture/hand_motion.py) 检测，需在约 0.26 秒的时间窗口内
位移超过设定阈值方可触发，并设有 0.55 秒的触发冷却时间。该类命令优先级高于静态手型手势。

| 动态意图        | 操作方式                 | 控制命令            | 角色响应                                                     |
| --------------- | ------------------------ | ------------------- | ------------------------------------------------------------ |
| **SWIPE_LEFT**  | 手部快速向左挥动         | `CMD_LOOK_LEFT`     | 向左追踪 · F01 · m03 · （无语音）· 追踪蓝光 · 头部转向左侧   |
| **SWIPE_RIGHT** | 手部快速向右挥动         | `CMD_LOOK_RIGHT`    | 向右追踪 · F01 · m04 · （无语音）· 追踪蓝光 · 头部转向右侧   |
| **RAISE_UP**    | 手部快速上抬             | `CMD_JUMP_SURPRISE` | 抬手惊喜 · F02 · m12 · “欸？手突然抬起来了” · 惊喜星光       |
| **MOVE_DOWN**   | 手部快速下移             | `CMD_BOW`           | 低头回应 · F01 · m14 · （无语音）· 冷静浅蓝                  |
| **PUSH_IN**     | 手部推近镜头（手部增大） | `CMD_COME_CLOSER`   | 靠近观察 · F06 · m18 · “你靠近了，我看得更清楚啦” · 追踪蓝光 |
| **PULL_OUT**    | 手部远离镜头（手部缩小） | `CMD_STEP_BACK`     | 后退留白 · F08 · m19 · （无语音）· 冷静浅蓝                  |

## 5. 舞台灯光（costume）对照

每个响应会切换舞台背景灯光氛围，由 CSS 实现（参见 `style.css` 中的 `data-costume`）。

| 标识    | 名称     | 适用响应                 |
| ------- | -------- | ------------------------ |
| `soft`  | 制服柔光 | 挥手、聆听、合影、赞许   |
| `calm`  | 冷静浅蓝 | 待机、委屈、低头、后退   |
| `blush` | 害羞粉光 | 害羞、拉钩、摸头         |
| `dance` | 舞台暖光 | 跳舞、应援、双手应援     |
| `focus` | 追踪蓝光 | 向左追踪、向右追踪、靠近 |
| `spark` | 惊喜星光 | 抬手惊喜                 |

## 6. 表情（expression）说明

`F01`–`F08` 为 Haru 模型自带的 8 个面部表情文件（`expressions/F0X.exp3.json`）。
本项目依据情绪类型分配使用：

- `F01`：自然 / 平静（待机、通话、追踪、低头）
- `F02`：认真 / 惊讶（聆听、惊讶、抬手）
- `F05`：愉悦 / 微笑（挥手、合影、赞许、跳舞、应援）
- `F06`：专注（靠近观察）
- `F07`：害羞（害羞、拉钩、摸头）
- `F08`：失落（委屈、后退）

## 8. 适配档案设计规范

Python 端仅输出与具体模型无关的通用命令（如 `CMD_WAVE`、`CMD_PET_HEAD`、`CMD_LOOK_LEFT`）；
适配档案负责将通用命令映射为特定模型的动作、表情、参数变化与语音文案。`haru.js` 即 Haru 模型
（Cubism 3）的适配档案，导出以下配置项：

| 配置项            | 职责                                             |
| ----------------- | ------------------------------------------------ |
| `MODEL_PROFILE`   | 模型路径、缩放比例、初始位置与默认状态           |
| `COMMAND_ALIASES` | 兼容旧命令名称，避免协议升级后立即失效           |
| `RESPONSE_MAP`    | 通用命令到动作、表情、语音及参数效果的映射       |
| `TEST_GROUPS`     | 页面本地测试按钮分组，并用于响应映射的完整性检查 |

### 更换模型的操作步骤

1. 将新模型资源放入 `web/models/<model-name>/`；
2. 复制 `haru.js`，创建新的适配档案文件；
3. 修改 `MODEL_PROFILE` 中的模型路径、缩放、位置与追踪参数；
4. 依据新模型的 `.model3.json`、动作文件与表情文件重写 `RESPONSE_MAP`；
5. 为所有可触发命令配置 `TEST_GROUPS`；
6. 在 `web/app.js` 顶部切换适配档案的导入；
7. 使用页面本地测试功能逐项验证动作、表情、参数与语音。

### 适配档案应包含的内容

- 模型资源路径、缩放比例与初始位置；
- 动作分组、动作索引或 `.motion3.json` 文件路径；
- 表情文件、参数 burst 效果与语音文案；
- 模型专有的追踪参数名称与幅度；
- 本地测试验证分组。

### 适配档案不应包含的内容

- WebSocket 连接与重连逻辑；
- UDP 协议解析；
- DOM 面板渲染；
- 通用语音开关；
- 通用的 `setParams()` 封装。

通过适配档案进行隔离后，更换 Live2D 模型通常无需修改 Python 手势识别链路与
Node.js Bridge 服务。
